# About

Socrates Dialogue includes four distinct systems: Socrates Dialogue, Socrates Markdown Language, SocraTSV, and SocraGUI.

Socrates Dialogue is a facet based dialogue system that exists to create conversations.

Socrates Markdown Language adds the ability to have waves, shaking, delays, and rainbow to text as it is displayed.

SocraTSV converts dialogue written in a tsv file to dialogue in the Socrates Dialogue format.

SocraGUI is a dialogue GUI that uses events from a dialogue manager to display a conversation on the screen.

These four systems can be used in a variety of combinations.

## Socrates Markdown Language

While writing the names and contents of dialogue, the following tags can be used to add flavor:

|Tag|Description|
|:---|:---|
|`[wave,INT]This text will wave[!wave]`|Makes the surrounded text wave with the passed INT overriding the default amplitude|
|`[shake,INT]This text will shake[!shake]`|Makes the surrounded text shake with the passed INT overriding the default intensity|
|`This text is displayed before the delay[delay,FLOAT][!delay] and this text is displayed FLOAT seconds after!`|Pauses the text as it appears for FLOAT seconds|
|`[gradient]This text will have a scrolling gradient specified in DialogueGradient[!gradient]`|Makes the surrounded text have a scrolling gradient (which by default is a rainbow)|

Socrates Markdown works with [TextMeshPro Rich Text](https://docs.unity3d.com/Packages/com.unity.textmeshpro@4.0/manual/RichText.html).

## SocraTSV

With lots of dialogue, it's important to be able to easily manage it. Instead of writing everything as constructor variables in a script, a .tsv can just be loaded once. Not only are .tsv files easier to manage and keep track of, but localization also becomes easier.

### Tagging

Cells may be tagged per cell, per column, or both. To make the contents of a column default to a certain tag, specify it above! For example, all of the rows in the first column will be treated as if it was following the 'name:' tag, unless otherwise specified. In the third column, all of the rows that aren't empty will be treated as if they were following 'ref:', but any rows that have a different tag will ignore the default, i.e. 'sound:dialogue_2' will not be interpreted as 'ref:sound:dialogue_2', but as 'sound:dialogue_2'.

## Quick Reference

|Tag|Description|
|:---|:---|
|`ref:REFERENCE`|Specifies that the line can be referenced via REFERENCE. This is used along with the 'next' and 'option' tags|
|`name:NAME`|Specifies that line's speaker's name is NAME. It will appear in the name text box when that line is displayed|
|`content:CONTENT`|Specifies that the line's content is CONTENT|
|`sound:SOUND_NAME`|Specifies that a sound called SOUND_NAME should be played when the line is displayed (note: make this audio source loop)|
|`next:REFERENCE`|Specifies the reference pointing to the next line in the conversation. By default, the next line will be the next line in the file, unless that line is empty, in which case the dialogue will end. Specifying nothing after 'next:' will make the dialogue end after that line|
|`option:TEXT,REFERENCE`|Specifies that the line will have an option with the label 'TEXT' that leads to the dialogue 'REFERENCE'. By using multiple of these, the conversation can branch (note: this is secretly an alias for the next: tag, so if only one option is specified, it won't show up as a single option for that line)|
|`event:FUNC_NAME(PARAMS)`|Specifies that the dialogue system should send a signal identified with the event tag FUNC_NAME and parameters PARAMS when reaching that line. (These events must be explicitly parsed and handled by a script)|

Anything in curly braces will be looked up from a token/value table specified in the file. For example, if there's a table like the one above, writing \{man\} anywhere will be referencing Rahul. If you reference a token that doesn't exist, it just won't replace it, i.e. 'name:\{nonexistenttoken\}' will just set the speaker's name to '\{nonexistenttoken\}'.

## DialogueBuilder

### int GetCurrentSectionBuilderCount
Returns the current number of section builders in the local list of `SectionBuilder`.

### SectionBuilder GetLastSectionBuilder
Returns the last `SectionBuilder` in the local list of `SectionBuilder`.

### DialogueBuilder WithSection
Adds the passed `SectionBuilder` to the local list of `SectionBuilder` and returns the instance of `DialogueBuilder`.

|Parameter|Description|Default|
|:---|:---|:---:|
|`SectionBuilder` sectionBuilder|The `SectionBuilder` to be added to the local list of `SectionBuilder`||

### DialogueBuilder WithSequentialSections
Adds each `SectionBuilder` in the passed list of `SectionBuilder` to the local list of SectionBuilder. Every section except for the last section gets a NextSection with the next `SectionBuilder`'s referenceId. This makes it so that long, sequential strings of lines don't have to be manually linked together.

|Parameter|Description|Default|
|:---|:---|:---:|
|`List\<SectionBuilder\>` passedSectionBuilders|The list of `SectionBuilder` to be added, automatically pointing to each other in sequence||

### DialogueBuilder WithSequentialSections
An overload for `WithSequentialSections` that accepts the `SectionBuilder`s as `params` so that a new list doesn't have to be manually made every time the function is called.

|Parameter|Description|Default|
|:---|:---|:---:|
|`params SectionBuilder[]` passedSectionBuilders|The `SectionBuilder` array to be passed to `WithSequentialActions` as a list||

### Dialogue Build() {
Iterates through the local list of `SectionBuilder` and builds each one. Each built `DialogueSection` is passed to the `DialogueManifest` to be potentially added to the map of `DialogueSection` by reference. Each `NextSection` is then linked to the `DialogueSection`s they're pointing to. These facets are linked here to support circular dependencies. The resulting `Dialogue` is returned.
